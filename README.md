# vli.bar — Live Lab

壁の向こうにオリジナルVRMのライブステージが現れるARデモ。PICO・Quest・対応AndroidはWebXR AR、Vision ProはWebXR VR、iPhoneはカメラで印刷マーカーを読む方式を使用します。
公開先: https://vli.bar/

## 開発

```sh
npm ci
npm run dev
npm test
npm run build
```

ローカル表示: http://localhost:5173 。HMD・スマホ実機でWebXRやカメラを使う場合はHTTPSで開いてください。Androidの開発時はUSBポート転送によるlocalhostも利用できます。

## ライブ

- オリジナルVRM「LUMI」、72秒・120BPMのステレオ楽曲「NEON DOOR」、30fpsのVRM Animation（.vrma）を同梱。
- 曲の再生時刻に合わせて、モーション・表情・幕を同期。歌唱・MC音声は含みません。
- PICOでは「壁を自動検出」→「ARでステージを開く」→壁の中心を見る。緑の候補枠が現れたらトリガーで配置し、もう一度押すと開演。以後のトリガーで停止・再生。
- 自動配置はマーカー不要です。WebXRの平面検出・垂直面のヒットテストを優先し、CPU深度が取得できる場合は局所的な垂直面を推定します。深度候補は安定してから配置できます。対応環境ではスマホの「部屋をスキャン」または候補がない時のHMDトリガーで、部屋スキャンを1回要求します。PICOのシステム側スキャン機能と、ブラウザへのデータ公開は別です。
- 自動で配置する前にサイドグリップを押すと「3点指定」へ切り替え。コントローラーの緑の点を、壁の数cm手前の左下→右下→左上に移動して各点でトリガー。舞台は下辺の幅に合わせて縦横同じ倍率で拡大します。
- 配置後のサイドグリップは停止・配置し直し。「距離を指定して配置」も選べます。「AR診断を保存」でAPIの利用状況をJSONへ保存できます。
- WebXRでの操作・対応条件・診断項目は [壁へのステージ配置](docs/wall-placement.md)。部屋全体の認識、永続アンカー、自動の共有空間合わせは未実装。iPhone向けの印刷マーカーARは下記を参照してください。
- PICO・Quest・Vision Pro・Android・iPhone実機での動作・性能は未確認。WebXR非対応環境でも3Dプレビューを利用できます。

## Vision Pro・Quest

- Vision ProのSafariではVRでステージを表示します。ボタンを見てピンチすると、配置・再生・配置し直し・終了や、モーションの収録を操作できます。許可された手の追跡から手首を取得します。現実の壁へ重ねるARや、壁の自動検出は行いません。
- Quest BrowserではパススルーARを優先し、ブラウザが提供する平面などを使って壁を検出します。空間設定と部屋情報の許可が必要です。コントローラーと手の操作に対応し、VR表示も選べます。
- 選択したVRMA・保存済みモーション・LAN出演者の再生と、音楽付き収録・ダウンロードは共通です。HMD観客は取得できた頭と手をLANで共有します。身体関節が取得できない部位は推定です。

操作・ブラウザの制約・検証範囲は[HMDでの利用](docs/headsets.md)。オフラインLANでは会場用CA証明書を信頼したHTTPS接続が必要です。Vision Pro・Quest実機の動作とWAN切断時の利用は未確認です。

## iPhone

iPhoneのSafariでは、3Dライブ、モーションのアップロード・プレビュー・ダウンロード、カメラによる身体モーション収録、LANでの出演・観覧に対応する実装を用意しています。iOSのWebXRは提供されていないため、ARは印刷マーカーと背面カメラを使います。[WebKitの対応状況](https://bugs.webkit.org/show_bug.cgi?id=309550#c2)

1. [印刷用マーカー](public/markers/index.html)を実際のサイズ・100%で印刷し、矢印を上にして壁へ貼ります。ARUCO_MIP_36h12のID 0です。黒い外枠の一辺は既定で15cm、白い余白を含む画像全体は18.75cmです。黒い外枠を実測し、アプリのマーカーサイズを合わせてください。
2. SafariでHTTPSのアプリを開き、マーカーARを開始してカメラを許可します。マーカー全体と白い余白が映るように背面カメラを向けます。マーカー中心が舞台の開口部の中心になります。
3. マーカーを見失うと舞台と観客の位置共有は止まるため、視聴中はマーカーを画面に入れます。選択したデモ・保存済みモーション・LAN出演者の動きを舞台へ表示できます。終了ボタンで通常ページへ戻ります。
4. 身体モーションの収録はARを終了してから「カメラを準備」を使います。全身が映るように端末を固定し、「収録を開始」。映像・マイク音声は保存・送信せず、姿勢を端末内で推定します。ファイルはSafariのダウンロードから「ファイル」アプリへ保存してください。

これは壁の自動検出や部屋のSLAMではありません。マーカーが見える範囲で位置を推定し、カメラ画角は近似値のため距離・大きさ・観客位置には誤差が残ります。ARと身体モーション収録は同時にカメラを使用できません。LANのスマホ観客は端末位置に顔の目安だけを表示し、手を共有しません。**iPhone実機での権限・印刷マーカーの追跡精度・音声・ファイル操作・性能は未確認です。**

2026-10-04の実装検証では、全229テストが成功。印刷SVGの大きさ・背景色・角度を変えた60条件で検出を確認しました。ブラウザでは合成映像を実カメラの代わりに入力し、実アプリの選択VRMA再生、追跡消失による一時停止、縦画面での再検出・再開、終了時のカメラ解放と選択保持、LAN観客の顔位置送信まで確認しています。これはSafari実機の動作確認を代替するものではありません。

追跡モジュールの合成映像テストは開発サーバーの`/tests/browser/marker-smoke.html`。実アプリの合成カメラ版は`node scripts/build-iphone-smoke.mjs`で別の一時ディレクトリへビルドできます。通常の`npm run build`・公開版・オフラインキットにはテスト用カメラを含みません。

## Androidスマホ

- ARライブ: ARCore対応機種のChromeとGoogle Play開発者サービス（AR）が必要です。「ARの操作方法」は通常「端末に合わせる」で使用し、必要なら「Androidスマホ（タップ）」を指定します。画面中央を壁へ向け、「ここに配置」→「ライブを再生」。画面内で再配置・音量・終了も操作できます。
- 自動検出できない場合は「距離指定へ」で切り替えます。距離指定は設定した距離へ置く補助で、壁の検出ではありません。3点指定はHMD用です。画面内の操作ボタンを表示するDOM overlayに対応しないブラウザでは、スマホARを開始しません。
- カメラ収録: WebXR ARとは別の機能です。スマホを固定し、全身が映る状態で「カメラを準備」→「収録を開始」。前面・背面カメラ、3・5・10秒の開始待ちを選べます。映像とアバターを同時表示し、映像は左右反転しません。
- MediaPipe Pose Landmarker Liteで身体を端末内推定し、最大15fpsで保存します。NEON DOOR付き72秒、または無音で最長3分。部屋の中の絶対移動は取得せず、マイク音声・映像の保存や送信も行いません。VRMA・生データJSON・プレビューはPICO収録と共通です。

ARの必要条件・カメラ操作・制約は [Androidでの利用](docs/android.md)。Android実機での精度・速度・権限画面・ファイル操作は未確認です。

## オフラインLANライブ

会場PCの中継サーバーへ、出演者1人と観客を合わせて最大16端末で接続できます。出演者のカメラ推定またはHMDの動きを各端末のVRMへ反映し、ARでは観客同士の顔アバターと、HMDで取得できた手を表示します。スマホ観客の顔は端末位置の目安です。映像・表情・音声・モデルファイルは送信しません。

会場ではインターネット・公開DNS・Pages・CDNを使用せず、PCと端末が同じWi-Fi/LAN内で通信します。開発環境で `npm run offline:pack` を実行すると、ビルド済みアプリ・Node・中継サーバー・VRM・音源・推定モデル/WASMを含むキットを作成します。今回のキットはMac / Apple Silicon用です。会場では `start.command` を実行するだけで、Node/npmの追加インストールは不要です。初回の証明書生成はOSのOpenSSLを使用します。

端末ごとに会場用CA証明書を手動で信頼させ、`https://会場PCのIP:8443/`を直接開きます。iPhoneは証明書のインストール後、「設定」→「一般」→「情報」→「証明書信頼設定」で会場用CAの完全な信頼も有効にします。全員で同じ壁の舞台の中心・幅を合わせ、マーカー中心は舞台の開口部の中心に揃えます。音楽は会場のスピーカー等を使用してください。詳しくは [オフラインLANの手順](docs/lan-live.md)、キット同梱の [会場用説明ページ](public/help/lan-offline.html)。ブラウザ・ARサービス・印刷マーカーは事前準備が必要です。Android・PICO・iPhone実機のCA信頼設定・WAN切断時のAR動作は未確認です。

## Motion Studio

以下は主にPICO・Questのコントローラーで収録する場合の操作です。手での操作やVision Proは[HMDでの利用](docs/headsets.md)、Android・iPhoneのカメラ収録は上記の導線を参照してください。

1. 「NEON DOORに合わせて収録」をオンにすると内蔵曲付き（72秒）、オフにすると無音。「収録用の曲を試聴」で確認し、PICOから「HMDでモーションを収録」。VRが使える場合はVRの収録室、なければARを利用。
2. 待機中からアバターが頭・手の動きを反映します。グリップで正面を合わせ直し、トリガーで3秒のカウントダウン。終了すると曲の再生と約30Hzのモーション記録が始まります。
3. 音楽付きは曲終了で自動保存してページへ戻り、無音は最長3分。途中終了はトリガー、または光線で「保存して戻る」を選択します。待機中のボタンは「ページへ戻る」です。XR終了時も取得済みデータを保持します。
4. 終了後は全身が見えるモーションプレビューを自動再生。音楽付き収録は同じ曲と同期し、一時停止・再生位置・繰り返しも連動します。VRMAと、生の取得記録JSONをダウンロードできます。
5. 他の端末から「モーションをアップロード」で取り込み。VRMA書き出しはVRM 1.0モデルに対応します。VRMA 1.0、計測JSON、旧デモJSONに対応。内蔵曲の参照はJSON・端末保存に保持し、VRMAには音声を含めません。外部VRMAは無音で再生します。
6. 保存・アップロード・前回保存の復元後は、「再生するモーション」が「保存・アップロードしたモーション」へ自動で切り替わります。「このモーションをARで確認」または上部の「選択モーションをARで確認」→壁に配置→スマホの「モーションを再生」／HMDのトリガーで確認できます。曲付きJSONの音楽同期と「プレビューを繰り返す」の設定はARにも反映し、一時停止・再開できます。AR終了後も選択を保持し、デモへ戻る時は明示的に選び直します。

アップロードは端末内の読み込みで、直近1件をIndexedDBへ保存します。JSONは32 MiBまで。ライブ表示と保存には同じ取得サンプルを使います。頭・コントローラーに加え、対応環境ではXRHandの手首と身体23関節を取得します。取得できない部位はIK等で推定し、マイク音声・動画・指・表情は収録しません。

HMDを外す・システム画面に移る・音声が中断するなどで収録が終了した場合は、保存したプレビューを停止状態で開きます。「プレビューを再開」で確認できます。

PICOのWeb身体追跡は、NVIDIA公式資料ではEnterprise機能・PICO Motion Trackers・対応OS/ブラウザが必要です。本アプリは任意機能として取得を試み、頭・手・身体の取得状態を表示します。PICO実機は未確認です。条件・操作: [モーション収録](docs/motion-capture.md)。交換形式: [VRMAの選定](docs/motion-formats.md)。

## 素材

- `public/demo/vli-performer.vrm`: 新規制作のオリジナルVRM。生成: `node scripts/generate-avatar.mjs`
- `public/demo/neon-door.wav`, `neon-door.vrma`: 新規作曲・振り付け。生成: `python3 scripts/generate-demo.py`（NumPyが必要）→ `node scripts/export-demo-vrma.mjs`。`motion.json` は生成元の内部データ。
- 利用条件: [VRM](public/demo/AVATAR-LICENSE.txt)、[音源・モーション](public/demo/CREDITS.txt)
- ユーザー提供VRMは `local-assets/` に保存し、Gitとビルド・配信から除外。ファイル選択による端末内読み込みは可能。

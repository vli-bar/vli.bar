# Vision Pro・Meta Questでの利用

同じWebアプリでライブの視聴、選択したVRMAの再生、頭・手を使うモーション収録、オフラインLANでの出演・観覧を利用します。端末名だけで機能を決めず、ブラウザのWebXR対応状況と、セッションで許可された機能を確認します。**Vision Pro・Quest実機での権限、操作、描画性能、音声、ファイル保存、会場用証明書の信頼設定は未検証です。**

| 環境 | ライブの表示 | 操作・追跡 |
|---|---|---|
| Vision ProのSafari | `immersive-vr`の仮想ステージ | ボタンを見てピンチ。許可された場合は頭と手首を取得 |
| Meta Quest Browser | `immersive-ar`のパススルーを優先。VRでも視聴可能 | コントローラーのトリガー、または手のポインターとピンチ |
| PICO Browser | 従来のARライブ・VR収録 | コントローラー、ブラウザから取得できる手・身体 |

## Vision Pro

visionOS 2以降のSafariはWebXRの`immersive-vr`、視線とピンチによる入力、手の追跡に対応しています。対応するOS・Safariへ事前に更新してください。[Safari 18のWebXR対応](https://webkit.org/blog/15865/webkit-features-in-safari-18-0/)

1. SafariでHTTPSのアプリを開き、VRでステージを開きます。没入表示と、必要なら手の追跡を許可します。
2. 舞台を置きたい方向へ顔を向け、候補枠を確認して配置します。VRでは指定した距離に仮想の舞台を配置します。
3. 表示されたボタンを見てピンチし、再生・一時停止、配置し直し、ページへの終了を操作します。収録時もボタンで開始・中止・保存・正面合わせを操作できます。

**Vision Proのこの表示は、現実の壁へ重ねるARではありません。** Safariが提供するVRを利用し、壁の自動検出や実写パススルーを要求しません。AR対応判定が誤って成功する問題もWebKitへ報告され、修正されています。アプリにはVRを直接選ぶ導線も用意し、AR開始に失敗した場合もページでVRを選び直せます。[WebKitのAR対応判定の修正](https://bugs.webkit.org/show_bug.cgi?id=305459)

視線とピンチの入力は、ピンチ中だけ存在する`transient-pointer`です。アプリは入力イベントの対象を使ってボタンを選びます。手の追跡を許可しなくてもボタンの操作は可能ですが、継続的な両手首の収録・LAN共有には`hand-tracking`の許可と追跡が必要です。ピンチ位置を手首の代わりに記録したり、視線を常時収録したりしません。[WebKitの入力仕様](https://webkit.org/blog/15162/introducing-natural-input-for-webxr-in-apple-vision-pro/)

## Meta Quest

1. Meta Quest BrowserでHTTPSのアプリを開きます。ARを使う場合はOSの空間設定を済ませ、ブラウザへ部屋の情報を許可してください。メニュー名称はOSのバージョンによって異なります。
2. 「壁を自動検出」でARを開始し、壁の中央へ顔を向けます。候補枠が安定して現れたら配置し、ライブを再生します。トリガー、または手のポインターでボタンを指してピンチします。
3. 壁が見つからない場合は、部屋スキャンの操作を選びます。ブラウザがスキャン機能を提供する場合に限り、1セッションにつき1回要求できます。部屋情報が出ない場合は距離指定へ切り替えるか、終了してVR表示を選べます。

Quest BrowserはパススルーARと平面検出を提供します。平面情報には空間設定とユーザー許可が必要で、部屋スキャン直後からすべての情報が出るとは限りません。自動検出の候補はブラウザの平面・ヒットテスト・CPU深度のいずれかを使い、床などを除外します。取得できない空間情報を推測して、検出済みとは表示しません。[MetaのMR仕様](https://developers.meta.com/vr/documentation/web/webxr-mixed-reality/)

ハンドトラッキングでは手のポインターでUIを指し、ピンチで操作します。手首を追跡できれば、コントローラーがなくてもモーション収録・LANでの手の共有に使います。暗さや遮蔽などで追跡を失った手は共有せず、再取得を待ちます。[Metaの手の追跡](https://developers.meta.com/vr/documentation/web/webxr-hands/)

## モーションとLANライブ

「HMDでモーションを収録」から収録室へ入ると、待機中からモデルへ頭・手の動きを反映します。音楽付き収録、VRMA/JSONの保存・読み込み、選択モーションの再生は従来と共通です。身体の情報がブラウザから出ない場合、胴体・脚は推定します。QuestやVision Proに全身追跡があるとは扱わず、指・表情・視線・映像・マイク音声は記録しません。詳しくは[モーション収録](motion-capture.md)。

会場PCのオフラインキットと同じWi-Fi/LANへ接続し、会場用CA証明書を端末で信頼したうえで、`https://会場PCのIP:8443/`を開きます。ブラウザ・OSの更新と証明書設定は会場前に済ませてください。アプリの素材・モーション・中継通信にインターネット、公開DNS、CDNは使いません。端末で信頼できない証明書の警告を無視する方法は、WebXRの利用条件を満たす手順にはなりません。[オフラインLANの準備](lan-live.md)

出演者はLAN参加後にHMD収録室を開くと待機中から配信できます。観客はARまたはVRで舞台を配置し、出演者とほかの観客のアバターを表示します。HMD観客は取得できた頭と手、スマホ観客は端末位置を目安にした顔だけを共有します。VRの配置は仮想ステージが基準で、現実の部屋との自動位置合わせではありません。同じ物理的な場所にいる観客の正確な位置を保証しません。

## 検証範囲

自動テストはAR/VRのセッション選択、任意機能の要求、視線とピンチの入力、手首の取得、選択モーションとLANの共通処理を確認します。合成したWebXR入力での検証は実機テストを代替しません。端末で問題が出る場合は「AR診断を保存」で、実際のセッション種別・許可された機能・追跡状態を確認できます。

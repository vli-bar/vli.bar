# Androidでの利用

Androidスマホでは、壁へステージを置くARライブと、カメラから動きを推定するモーション収録を利用できます。2つは別の機能です。iPhoneは[印刷マーカーARとカメラ収録](../README.md#iphone)を利用します。

| 機能 | 必要な環境 | 操作 |
|---|---|---|
| ARライブ | ARCore対応Android、Chrome、Google Play開発者サービス（AR）、WebXR DOM overlay | 画面中央を壁へ向け、画面内のボタンで配置・再生 |
| カメラ収録 | HTTPS、カメラの使用許可、同梱の姿勢推定処理を実行できるブラウザ | スマホを固定し、映像とアバターを見ながら収録 |
| 3Dプレビュー・モーションの読み込み | WebGLを利用できるブラウザ | 通常ページで再生・停止・シーク |

カメラ収録自体はARCoreやWebXRを使いません。AR非対応端末でも利用を試せますが、すべてのAndroid機種での動作を保証するものではありません。

## ARライブ

1. Chromeで[公開ページ](https://vli.bar/)を開きます。ARCore対応機種でGoogle Play開発者サービス（AR）がインストール・有効化されていることを確認してください。WebXRはHTTPSなどの安全なコンテキストを要求します。[Google公式のWebXR必要条件](https://developers.google.com/ar/develop/webxr/requirements)
2. 「ARの操作方法」は「端末に合わせる」を選びます。自動選択が合わない場合は「Androidスマホ（タップ）」を指定してください。「舞台の配置方法」で自動検出または距離指定を選び、幅・距離を調整します。
3. ARを開始し、画面中央の印を壁へ向けます。自動検出の候補枠が表示されたら「ここに配置」を押します。指でタップした画面位置を壁の位置として使用する方式ではありません。
4. 「ライブを再生」で開演します。音量、停止・再生、「置き直す」、「ページへ戻る」は画面内で操作できます。
5. 壁が見つからない場合は「距離指定へ」で切り替え、画面中央を置きたい方向に向けて配置します。設定した距離へ舞台を置くため、実際の壁との位置合わせは手動です。同じARセッション中に自動検出へ戻すこともできます。

3点指定はコントローラーを使うHMD向けです。スマホ操作で3点指定が選ばれていた場合は距離指定へ切り替えます。自動検出はブラウザの平面情報・ヒットテストが提供される場合に利用し、未対応と未検出を画面に表示します。[壁配置の詳細](wall-placement.md)

スマホARでは配置・再生・終了のボタンを表示するため、WebXRの`dom-overlay`を必須機能として要求します。未対応の場合はARの開始に失敗し、通常ページで理由を表示します。平面検出・ヒットテストは任意機能なので、それらが未提供でも距離指定を利用できます。[DOM Overlays仕様](https://immersive-web.github.io/dom-overlays/)

PICOもAndroid系のユーザーエージェントを返すため、OS名だけでスマホと判定しません。「端末に合わせる」ではimmersive VR対応を調べ、対応する場合はHMDのコントローラー操作を選びます。手動選択が優先されます。

## カメラからモーションを収録する

1. スマホを固定し、1人の頭から足まで映る明るい場所を用意します。「カメラ」で前面・背面を選択します。カメラを切り替える場合は、一度終了してから選び直してください。
2. 「NEON DOORに合わせて収録」で音楽の有無を選びます。オンは内蔵曲に合わせた72秒、オフは無音で最長180秒です。「収録用の曲を試聴」で音量を確認できます。
3. 「カメラを準備」を押し、カメラの使用を許可します。姿勢推定モデルの読み込み後、カメラ映像とアバターを同時に表示します。前面カメラでも映像を左右反転しません。
4. 「開始まで」を3・5・10秒から選び、「収録を開始」を押します。カウントダウンの間に全身を画面に入れます。曲付きの場合は音楽とモーションを同じ時間軸で記録します。
5. 途中で終える場合は「保存してカメラを終了」を押します。曲の終了または時間上限でも収録を終了します。通常終了後は共通のモーションプレビューで再生・一時停止・シークできます。
6. 「VRMAをダウンロード」で他のVRM対応ツールへ渡せるモーションを保存します。付属モデルなどVRM 1.0で書き出してください。取得記録や収録時の曲設定を保持する場合は「生の計測データ JSON」も保存します。VRMAには音源を含めません。

ページが非表示になったり、カメラが切断されたりした場合は停止し、取得済みモーションを保持します。データが得られる前に終了した場合は、新しいモーションは作成されません。カメラ収録とXRセッションは同時に開始できません。

## 推定の範囲とデータ

実装は`@mediapipe/tasks-vision` 0.10.32とPose Landmarker Liteを使用します。JavaScript、WASM、モデルは同じサイトから読み込み、映像の処理は端末のブラウザ内で行います。推定・保存は最大15fpsで、実際の頻度は端末性能によって下がります。カメラの有効な隣接姿勢間だけ最大0.5秒まで補間し、明示的な欠測は維持します。音楽付きでは推論の処理時間を記録時刻から補正しますが、カメラ自体の遅延は端末によって残ります。

モデルが出力する3D位置は腰の中心を原点とする身体姿勢の推定です。アプリでは腕・脚・胴体の方向をアバターへ適用しますが、部屋の中を歩く移動量やジャンプの絶対高さは復元しません。奥行き、隠れた部位、骨のひねりには制約があります。顔の表情・指の関節も収録しません。[MediaPipe Pose Landmarker公式資料](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)

生データJSONは既存の`vli.motion-capture`バージョン1を使い、カメラ収録を`referenceSpace: 'camera'`、姿勢の入力元を`source: 'camera-pose'`で区別します。位置は推定として扱い、従来のPICOデータも引き続き読み込めます。保存されるのはモーションで、カメラ映像・静止画・マイク音声ではありません。カメラへのアクセス時もマイクを要求しません。

直近のモーション1件はこのブラウザのIndexedDBに保存します。「モーションをアップロード」は端末内へのファイル読み込みであり、サーバーへの送信・共有は行いません。別の端末で利用する場合はファイルをダウンロードしてください。[収録形式・音楽との同期](motion-capture.md)

## 検証状況と開発時の接続

自動テストではスマホ向けセッション設定とHMD設定の維持、画面中央の候補への配置、配置モードの切り替えを確認しています。デスクトップブラウザでは、公式テスト画像から生成したcanvas映像を実MediaPipeモデルへ入力し、33点・身体23関節の推定、約2秒の収録、JSON検証、カメラ停止を確認しました。生成したデータを通常画面へ読み込み、アバターのプレビューも確認しました。390px幅のレイアウトを確認しています。**Android実機のカメラ権限・AR配置・動く人の推定精度・速度・ダウンロードは未確認です。** 自動テストによる確認と実機での動作確認は区別してください。

開発時にPCのViteサーバーへ接続する場合、LAN内のHTTPアドレスだけでは安全なコンテキストになりません。HTTPSを利用するか、Chrome DevToolsのUSBポート転送でAndroid側の`localhost:5173`から開いてください。AndroidエミュレーターはWebXRの検証環境にはできません。[Google公式の開発環境設定](https://developers.google.com/ar/develop/webxr/requirements)

開発用の実モデル確認ページは `/tests/browser/camera-smoke.html` です。`tests/browser/fixtures/README.md` に従って任意の公式テスト画像を取得してから、Viteサーバーで開いてください。テスト用ページ・画像は本番ビルドに含まれません。

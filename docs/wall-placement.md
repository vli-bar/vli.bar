# 壁へのステージ配置

WebXRのARライブには、自動検出、コントローラーによる3点指定、距離指定の3つの配置方法があります。Androidスマホ・PICO 4 Ultraでは、ブラウザが公開する平面・交点・深度を実行時に確認して、印刷マーカーなしで壁の候補を探します。iPhoneのSafariでは別の[印刷マーカーAR](../README.md#iphone)を使用します。**Android・PICO実機での壁検出・配置精度・操作は未確認です。**

## 自動検出で配置する

1. 通常画面の「舞台の配置方法」で「壁を自動検出」を選び、舞台の幅を設定します。
2. 「ARでステージを開く」を押し、置きたい壁へ視点の中央を向けます。Androidスマホは端末を、HMDは頭をゆっくり動かして、周囲の面を読み取れるようにします。
3. 緑の候補枠が現れたら、Androidは「ここに配置」、HMDはトリガーで配置します。深度から推定する場合は、候補が3フレーム以上かつ約350ms安定するまで待ちます。自動選択は視点の正面方向を使うため、指で別の画面位置をタップしたり、コントローラーだけを壁へ向けたりしても候補位置は変わりません。
4. Androidは「ライブを再生」、HMDはもう一度トリガーを押すと開演します。配置後はAndroidの画面内ボタンで再生・停止・置き直し、HMDのトリガーで停止・再生、サイドグリップで停止・配置し直しを行います。

Androidの「部屋をスキャン」は、`XRSession.initiateRoomCapture()`が提供され、必要な機能が許可されている場合に使用できます。HMDでは候補がない状態のトリガーで同じ要求を行います。要求はそのXRセッション中に1回だけです。端末側の案内が出たら従ってください。スキャン機能の非対応と、対応しているが候補がない状態は区別して表示します。APIの呼び出しが完了しても、壁データの取得を保証するものではありません。

自動配置が確定する前にサイドグリップを押すと、3点指定へ切り替わります。配置後のグリップ操作では自動方式のまま再配置します。3点指定・距離指定でのグリップ操作は、それぞれの方式のままやり直します。方式を選び直す場合はARを終了して通常画面で変更します。

## コントローラーで3点を指定する

壁の左下・右下・左上として使う位置を、実際にコントローラーを移動して指定します。壁全体の四隅である必要はありません。

1. 「コントローラーで3点を指定」を選んでARを開始するか、自動配置の確定前にサイドグリップを押します。
2. コントローラーに表示される**小さな緑の点**を、舞台の**左下**にしたい位置へ移動し、トリガーを押します。
3. 同じ高さの**右下**へ緑の点を移動し、トリガーを押します。
4. 最初の左下のほぼ真上となる**左上**へ緑の点を移動し、トリガーを押します。
5. 配置された舞台を確認し、もう一度トリガーを押して開演します。

緑の点はコントローラーのWebXR照準原点（`targetRaySpace`）を表しています。遠くの壁を指す方式ではありません。各点では、緑の点を**壁の数cm手前**まで移動してください。コントローラー本体や手を壁へ押し付ける必要はありません。3点とも同じ程度だけ壁から手前に離します。

舞台の下辺の中心が左下・右下の中点になり、**下辺の幅を使って舞台全体を同じ倍率で拡大縮小**します。左上は上方向・壁面の向きと入力の妥当性を確認するために使います。指定した高さへ舞台を引き伸ばす処理はありません。

指定できる下辺の幅は0.4〜6m、左下から左上への高さは0.4〜4mです。下辺の傾き、左上の横ずれ、面の傾きが大きい場合は3点を取り直します。上下左右の判定はおおむね20度以内を許容します。届く範囲に小さい舞台を置いても体験できます。

## 距離を指定して配置する

「距離を指定して配置」では、幅と「目の前からの距離」を設定してからARを開始します。目の前の指定距離に候補枠が現れるので、トリガーで配置し、もう一度押すと開演します。この方式は実際の壁面や奥行きを測りません。

自動・距離指定時の幅スライダーは1〜4m、距離指定時の距離は1〜5mです。幅・距離・配置方式の設定はXR中に変更できません。ARを終了して変更してください。

## 実装しているAPIと判定

自動方式の`immersive-ar`開始時には、`local-floor`、`plane-detection`、`hit-test`、`depth-sensing`を`optionalFeatures`として要求します。深度は`cpu-optimized`を指定し、`float32`または`luminance-alpha`形式、`matchDepthView: true`で要求します。描画・配置の基準空間は`local`です。追加機能が提供されない場合も、ARセッション自体の開始を妨げない構成です。

候補は**ブラウザが返す平面 → 垂直面へのヒットテスト → 深度からの平面推定**の順に探します。ただし、ブラウザの意味ラベルで家具などの非壁面が正面を遮っていると分かった場合は、後続の推定に置き換えず、壁が見える位置へ向け直す案内を出します。実際に取得できたデータだけを使い、いずれも取得できない場合は3点指定または距離指定を案内します。

| 入力 | 配置への利用 |
|---|---|
| `XRFrame.detectedPlanes` | 各平面のポリゴンと`getPose(plane.planeSpace, referenceSpace)`を取得。視点から正面に伸ばした線がポリゴン内部に当たる、最も近い垂直面を候補にします。家具などの既知の意味ラベルは候補から除外し、ラベルがない垂直面も利用します。 |
| `XRSession.requestHitTestSource()` | `viewer`空間・`entityTypes: ['plane']`で要求。平面ポリゴンから候補を得られない場合に、`getHitTestResults()`の垂直面への交点を使います。 |
| `XRFrame.getDepthInformation()` | CPU用の深度が提供される場合に、視点中央周辺の距離から局所的な垂直平面を端末内で推定します。深度が欠ける、平面に揃わない、床・天井に近い、中央に遮蔽物があるなどの候補は採用しません。 |
| `XRSession.initiateRoomCapture()` | 自動方式でAndroidの「部屋をスキャン」、またはHMDの候補がない時のトリガーから1回だけ要求。APIの存在と`plane-detection`の許可状態を確認します。 |
| コントローラーの`targetRaySpace` | 3点指定で、トリガーを押した時点の原点座標を記録します。 |

自動候補は視点から0.25〜8m、垂直から20度以内の面に限定します。平面の`semanticLabel`が利用できる場合は既知の家具等を除外しますが、アプリ自身が画像から壁・家具・扉を分類するわけではありません。ラベルのない面、ヒットテスト、深度推定では「垂直な面」が壁とは限らないため、候補枠を確認して配置してください。利用できるデータが空の状態と、APIを利用できない状態を区別して表示します。

深度推定は少数の距離サンプルに平面を当てはめるRANSACを使用し、揃った面の広がりと中央付近までの連続性を確認します。時間方向にも位置・向きが安定した候補だけを採用します。取得していない領域や物陰を埋めて壁全体を復元する処理ではありません。深度画像・サンプル座標は保存せず、外部やLANの他端末へ送信しません。[WebXR Depth Sensing仕様](https://immersive-web.github.io/depth-sensing/)

WebXR平面のポリゴンは`planeSpace`のXZ平面、法線は+Yです。取得した法線を舞台の正面+Zへ変換し、舞台が観客側を向くように配置します。平面の属性が更新されていなくても、その姿勢は毎フレーム取得します。[WebXR Plane Detection仕様](https://immersive-web.github.io/plane-detection/)

ヒットテストで取得するのは交点の姿勢です。壁の幅・高さや部屋全体の間取りは得られません。[WebXR Hit Test仕様](https://immersive-web.github.io/hit-test/)

Chrome 147の公式リリースノートにはWebXR平面検出の追加が記載されています。ただし、Chromeのバージョンだけで全機種の平面・深度取得を保証するものではありません。端末、ARサービス、権限、実行中に提供されるデータを確認します。[Chrome 147リリースノート](https://developer.chrome.com/release-notes/147?hl=ja)

## PICOの部屋スキャンとの関係

PICO公式はPICO 4 UltraのWebXR・MR API対応を案内しています。一方で、PICO Browserが平面検出・ヒットテストを提供することを個別に保証する資料は確認できていません。端末のOS・ブラウザ・権限・実際に返るデータを確認する必要があります。[PICO 4 Ultra公式資料](https://developer.picoxr.com/pico4-ultra/)

PICOのRoom Captureは部屋の壁・床・家具などを認識し、SDKから場面データを利用する仕組みです。該当する公式のScene Capture説明はUnity Integration SDK向けです。システムでスキャンが完了したことと、そのデータがWebページに公開されることは別です。[PICO Scene Capture公式資料](https://developer.picoxr.com/document/unity/scene-capture/?v=3.0.0)

今回の自動配置が扱うのは、ブラウザから取得できた面・交点と、深度から推定した局所的な垂直面です。部屋全体を復元して間取り・家具を分析する機能ではありません。推定処理はアプリ内で完結し、会場用キットのインターネット不要なLAN構成を維持します。

## AR診断を保存する

ARを体験した後、XRを終了し、通常画面の「AR診断を保存」を押すと`vli-ar-diagnostics.json`を端末へ保存します。サーバーへの送信は行いません。

診断には時刻、ブラウザのUser Agent、HTTPS等の安全なコンテキストか、AR/VR対応判定、要求後に有効になった機能一覧（取得可能な場合）、平面API・ヒットテスト・深度推定・部屋スキャンの利用状況、平面件数・垂直面件数、位置追跡の成否、採用した配置方式を含みます。深度の項目は利用状態と、サンプル数・平面への当てはまりなどの集計値です。

Motion Studioの収録を使用した場合は、頭の取得状態、左右の手の入力元、身体APIの状態、身体関節件数・位置推定件数も含みます。身体は`body-tracking`草案から実際に取得できた情報だけを数えます。利用条件は[モーション収録](motion-capture.md)を参照してください。

部屋画像・映像・深度画像・深度サンプル座標・平面ポリゴン・3点の座標・頭や手や身体関節の座標と回転は含みません。壁配置と収録の各欄は、そのページで最後に使用した各機能の状態を表し、再読み込みすると初期状態に戻ります。

## 制限

- 候補枠の中心が平面内にあることは確認しますが、舞台の枠全体が壁のポリゴン内に収まるかは判定しません。幅は利用者が調整します。
- 舞台の基準サイズは幅2.4m・高さ2.5mです。実際の舞台の高さは`指定幅 × 2.5 / 2.4`になります。3点指定の左上の高さとは一致しない場合があります。
- 永続アンカーやセッションをまたぐ位置保存はありません。ARを終了した時や基準空間がリセットされた時は、配置をやり直します。LANで観客の位置を共有する場合も、端末間の自動位置合わせは行わず、全員で同じ舞台中心・幅・向きを合わせます。[LANでの位置合わせ](lan-live.md#全員で舞台の位置を合わせる)
- 位置追跡を失った時は舞台を隠します。配置後の舞台はその場の基準空間に固定され、平面の再推定へ追従するアンカーではありません。
- このWebXRの壁配置では、カメラ画像による部屋分析や印刷マーカー認識を使いません。iPhoneには別の[カメラによる印刷マーカーAR](../README.md#iphone)を用意しており、マーカーが見える間だけ舞台と端末位置を追跡します。これは部屋のSLAM・壁自動検出ではなく、WebXRの画像追跡APIも使用しません。
- 深度推定は、反射・透明面、暗所、遮蔽物、動く人、奥行き欠測によって失敗したり揺れたりします。平面・深度APIが未提供の端末で自動検出できるようにするものではありません。
- Android・PICO 4 Ultra実機で、権限・タップ・トリガー・グリップ・追跡・ダウンロード・配置精度を確認する必要があります。ブラウザ上の模擬テストだけでは実機の対応を保証できません。

# モーションの標準形式

vli.bar のアバター用モーションの交換形式は **VRM Animation 1.0（`.vrma`）** とします。PICO で収録したデータからアバターの姿勢を計算し、VRMA としてダウンロードします。他のツールが作った VRMA も読み込み、表示中の VRM に適用します。

VRMA は VRM コンソーシアムが定義する、glTF 2.0 を基礎としたアバターアニメーション形式です。骨・表情・視線の対応を保持できます。VRM アバターの共有が目的なので、この対応を独自に決めずに済むことを採用理由とします。[VRMA 1.0 公式仕様](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm_animation-1.0/README.md)

## 比較と採用範囲

| 形式 | 保存・伝送する内容 | vli.bar での判断 |
|---|---|---|
| **VRMA 1.0** | glTF のアニメーションに、VRM の人型骨・表情・視線の対応を付けたファイル | **採用**。VRM 向けモーションの読み込み・保存の基本形式。実装する属性とファイル制限は下記。 |
| **BVH** | 階層を持つ骨格と、そのアニメーション | Blender などとの骨格モーション交換に有用。軸・スケール・回転順と、VRM の骨への対応を合わせる工程が必要なため、今回の直接入出力には含めない。[Blender 公式マニュアル](https://docs.blender.org/manual/en/4.2/addons/import_export/anim_bvh.html) |
| **glTF 2.0 / GLB** | ノードの移動・回転・拡大縮小、モーフのアニメーション | VRMA の基盤として使用。glTF コアだけでは対象ノードが VRM のどの人型骨かを表現しないため、汎用 GLB をそのまま別の VRM へ適用する機能にはしない。[Khronos 公式仕様](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc#animations) |
| **FBX** | 制作ツール間で交換する3Dアセットやアニメーション | 制作工程の候補。今回のブラウザの直接入出力には含めない。制作ツール側で骨の対応と姿勢を確認し、VRMA に変換する運用を想定する。[Autodesk 公式説明](https://www.autodesk.com/products/fbx/overview)、[公式 SDK](https://aps.autodesk.com/developer/overview/fbx-sdk) |
| **VMC Protocol** | OSC over UDP/IP による、骨や表情などのリアルタイム通信 | 将来の生出演の連携候補。収録ファイルの形式とは別に扱う。ブラウザ向け中継と時刻同期を別途設計する方針で、今回のMVPには含めない。[VMC 公式仕様](https://protocol.vmc.info/english.html) |

上表の採否・変換経路・将来構成は、このプロジェクトの設計判断です。各形式そのものが本アプリへの対応や変換結果を保証するものではありません。

## VRMA の扱い

- `.vrma` は自己完結した GLB として扱い、`VRMC_vrm_animation.specVersion` を `1.0` とする。
- 人型骨の休止姿勢と階層を保存し、骨の回転と腰の移動をアニメーション化する。一般の関節位置をそのまま全骨の移動トラックには変換しない。
- 書き出し対象は、VRM に適用した骨の姿勢、腰移動、および対応している表情。視線専用トラックは今回の書き出し対象外。
- 計測JSONや旧振り付けJSONからのVRMA書き出しは、現在 **VRM 1.0モデルのみ** に対応する。VRM 0.xを使用中は、同梱のLUMIを読み込んで書き出す。標準VRMAの読み込みにはライブラリのVRM 0.x向け変換を使用するが、任意の旧モデルでの互換性は個別確認が必要。読み込んだVRMAをそのまま再ダウンロードする操作はモデル変換を行わない。
- モーションのサイズや軸は、表示用ステージの配置・拡大率から切り離す。画面上でステージを移動しても、保存した動きの座標を変えない。
- 音源・映像・VRMモデル本体をモーションファイルには含めない。ライブの音声同期や舞台演出はアプリの再生タイムラインが管理する。
- 取り込み・再生・書き出しの互換性は、配布VRMだけでなく、休止姿勢・体格が異なるVRMと、外部ツール製VRMAでも検証する。自作ファイルの読み直しだけでは外部互換性の確認完了としない。

このMVPの取り込み上限は20 MiB・3分・256ノード・1アニメーションです。外部バッファ・画像参照やモデルメッシュを含むファイルは対象外です。これらはアプリ側の制限で、VRMA仕様全体の制限ではありません。

異なる骨の休止回転や体格への対応にはリターゲット処理が必要です。これは拡張子を変えるだけでは実現できません。[VRM公式の姿勢変換資料](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm_animation-1.0/how_to_transform_human_pose.md)

## PICO の生データを残す理由

WebXRから取得した頭部・コントローラーまたは手首と、対応環境では身体23関節を使ってVRMAを生成します。未取得部位はIKなどで推定します。身体APIの値にも端末側の推定が含まれうるため、書き出した全身の姿勢が全身の実測値になるわけではありません。身体は関節間の位置方向からVRMへ適用し、生の関節回転を直接コピーしません。骨軸まわりのひねりは未対応です。

既存のJSON保存は、**再処理用の取得記録**として残します。頭・両手と任意の身体関節、入力元、欠落フレーム、追跡フラグ、記録時の参照空間を保持します。従来の身体データがないJSONも読み込めます。上限は32 MiBです。これはアバター用の交換標準ではなく、VRMAに変換した姿勢だけから失われる元データを残す用途です。ライブ表示と保存は同じサンプル・校正原点を使用します。

制作済み振り付けの内部JSONも、既存デモの生成・検証用途に限定します。外部向けのモーション配布では VRMA を用い、新しい独自交換形式は設けません。生データの記録条件と推定範囲は [PICOモーション録画](motion-capture.md) を参照してください。

## 互換性確認

公式ライブラリの [外部VRMAサンプル](https://github.com/pixiv/three-vrm/blob/dev/packages/three-vrm-animation/examples/models/test.vrma) を、アプリのインポーターと再生処理で読み込んで確認しました。3秒のクリップを解析でき、LUMI上で0.5秒時点の右上腕の90度回転と1.5秒時点のhappy表情が反映されます。このサンプルは休止回転を持つ骨を含み、生成したデモの自己往復だけとは異なる確認です。サンプルファイルそのものは本リポジトリへ再配布していません。

任意の制作ソフト・任意のVRMとの互換性や、PICO実機での録画精度まで保証する結果ではありません。実機で収録した動きと制作ツールへの受け渡しは引き続き確認が必要です。

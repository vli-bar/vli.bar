# モーション収録

PICOでは頭部、コントローラーまたは手首をWebXRから取得し、対応ブラウザでは身体関節も使用します。取得できない胴体・脚などは推定です。Androidスマホでは、通常ページのカメラから身体の姿勢を推定して収録します。どちらも待機中からアバターが動きを反映し、内蔵曲を聞きながら踊れます。マイク音声・映像・部屋画像・表情・指の動きは記録しません。**PICO 4 Ultra・Android実機でのAPI提供・精度・操作・ダウンロードは未確認です。**

## PICOの操作

1. HTTPSで開き、「NEON DOORに合わせて収録」を確認します。オンは内蔵曲付き（72秒）、オフは無音です。「収録用の曲を試聴」で音量を確認してから「HMDでモーションを収録」を選びます。利用できればVR、なければARで収録室を開きます。
2. 待機中のアバターで頭と左右の手を確認します。正面を合わせ直す時は、待機中にサイドグリップを押します。
3. トリガーで3秒のカウントダウンを開始します。終了すると曲とモーションの記録が同時に始まります。音楽の準備や頭部追跡ができない間は開始を待ちます。カウントダウン中に再度押すと開始を取り消します。
4. 音楽付き収録は曲の終了時に自動保存してページへ戻ります。無音は最長3分です。途中で終える時はトリガーを押します。画面下の「ページへ戻る」をコントローラーの光線で選んでも終了でき、収録中は「保存して戻る」と表示されます。
5. 終了後は収録した動きを自動再生します。音楽付き収録は同じ内蔵曲と合わせて再生し、無音収録は音を出しません。ポータルの枠で切り取らない全身表示で確認し、一時停止・再生位置・繰り返しを操作できます。
6. 他のツールとの交換用はVRMA、再処理用の取得記録はJSONをダウンロードします。VRMA書き出しにはVRM 1.0モデルを使用します。**VRMAには音声を含めません。** 内蔵曲との対応を保持して別の端末で再生する場合は、JSONを使います。

直近1件はIndexedDBへ保存します。アップロードは端末内への読み込みで、サーバーへ送信・共有しません。基準空間がリセットされた場合は収録を終了し、それまでのデータを保持します。

収録中にHMDを外したりシステム画面へ切り替えたりした場合や、音声が中断された場合は、取得済みデータを保存して終了します。この場合、ページのプレビューは停止状態で開きます。「プレビューを再開」で確認してください。

## Androidのカメラ収録

スマホを固定し、1人の全身が映る状態で「カメラを準備」を押します。許可後に映像とアバターを同時表示します。前面・背面カメラは停止中に選び、開始まで3・5・10秒を指定して「収録を開始」を押してください。カメラ映像は左右反転しません。

NEON DOOR付きは72秒、無音は最長180秒で、最大15fpsの推定モーションを保存します。途中終了は「保存してカメラを終了」。終了後のプレビュー、VRMA書き出し、生データJSON、端末内保存はPICO収録と共通です。ページの非表示やカメラ切断時にはカメラを停止し、取得済みデータを保持します。

WebXRのARライブとは別機能で、カメラ収録自体にARCoreは使いません。同じサイトに同梱したMediaPipe 0.10.32とPose Landmarker Liteを端末内で実行します。映像から身体姿勢を推定するため、部屋の絶対座標での歩行やジャンプは復元しません。推定の制約、対応条件、プライバシーは[Androidでの利用](android.md)を参照してください。

## 保存・アップロードしたモーションをARで確認する

1. 収録を保存するか、「モーションをアップロード」で読み込みます。前回の端末内保存を復元した場合も含め、「再生するモーション」が「保存・アップロードしたモーション」へ自動で切り替わります。
2. Motion Studioの「このモーションをARで確認」、または上部の「選択モーションをARで確認」を押します。
3. 壁に舞台を配置し、Androidでは「モーションを再生」、HMDではトリガーを押します。同じ操作で一時停止・再開できます。

「プレビューを繰り返す」の設定はAR再生にも反映します。有効な内蔵曲の参照を持つJSONは「収録時の音楽を再生」がオンなら曲と同期し、外部VRMAは無音です。AR終了後もモーションの選択を保持します。デモへ戻る時は「再生するモーション」で「デモ：NEON DOOR」を選ぶか、「デモに戻す」を押してください。壁配置の方法は[壁へのステージ配置](wall-placement.md)を参照してください。Android・PICO実機でのこの操作は未確認です。

## 音楽付きの収録と再生

「NEON DOOR」はアプリに同梱した音源です。音楽付きの収録では曲と動きの時刻を合わせ、ページでのプレビューでも曲とモーションを一緒に一時停止・再開・シーク・繰り返し再生します。途中終了した場合は、取得した範囲だけをプレビューします。

ブラウザが音楽の開始を許可しなかった場合は「プレビューを再開」で再試行できます。「収録時の音楽を再生」をオフにすれば、モーションだけを確認できます。この設定を切り替えると、プレビューは先頭から始まります。

曲の参照と開始位置は生データJSONおよび端末内の保存に保持します。音源ファイルそのものやマイク音声は保存しません。外部から読み込んだVRMA、曲の参照がないJSON、無音を選んだ収録は無音でプレビューします。VRMAと曲を別の制作ソフトで組み合わせる場合は、デモ素材欄の音源WAVを別途利用してください。

## 取得と推定の範囲

| 入力 | 取得方法と反映 |
|---|---|
| 頭 | `getViewerPose()`。頭の向きと移動を使用。 |
| コントローラー | `getPose(gripSpace, referenceSpace)`。腕は手の位置を目標にした2ボーンIKで推定。 |
| 手首 | 任意機能`hand-tracking`。`XRInputSource.hand.get('wrist')`と`getJointPose()`で取得できればコントローラーより優先。指関節は収録しない。 |
| 身体 | 任意機能`body-tracking`。`XRFrame.body.get(jointName)`で得る空間を`getPose()`で読み、主要23関節を保存。未提供・追跡待ち・取得エラーを区別し、未取得部位は頭と手から推定。 |
| スマホカメラ | `getUserMedia({audio: false, video: ...})`とMediaPipeによる身体姿勢の推定。頭・手首・身体へ変換し、すべて位置推定として保存。映像そのものは保存しない。 |

身体データは関節間の位置方向から骨の向きと腰の位置を合わせます。端末の生クォータニオンをVRMへ直接コピーしません。骨軸まわりのひねりは再現しません。コントローラー・手首の回転は生データに残しますが、その回転をそのままVRMの手首へ適用する処理もありません。

身体API自体が未観測関節を推定する場合があります。「身体23関節を取得」は全関節の独立した実測を意味しません。`emulatedPosition`は位置推定のフラグであり、回転の精度や全身の実測を保証しません。[WebXR Device API](https://www.w3.org/TR/webxr/)、[Hand Input仕様](https://immersive-web.github.io/webxr-hand-input/)、[Body Tracking草案](https://immersive-web.github.io/body-tracking/)

## PICO の対応条件

NVIDIA公式のIsaac Teleop資料では、WebXRの身体追跡に**PICO 4 Ultra Enterprise、またはEnterprise機能を有効化した一般向け機体**と、PICO Motion Trackersを要求しています。一般向け機体では、トラッカーを接続・校正しただけではブラウザが`body-tracking`を許可しないと説明されています。案内される動作条件は**PICO OS 15.4.4U以降・PICO Browser 4.0.40以降**です。これはNVIDIAの当該構成の要件であり、一般向けOSのバージョン番号に読み替えるものではありません。[NVIDIA 対応機器](https://nvidia.github.io/IsaacCapture/main/overview/ecosystem.html)

同資料は最少2個の足首トラッカー、3個構成では足首2個と腰、5個構成ではさらに手首または太ももを案内しています。2個構成では上半身などに推定が入り、腰・座位・寝姿勢の精度には制約があります。端末側でペアリング・校正を済ませてください。[NVIDIA Body Tracking](https://nvidia.github.io/IsaacCapture/main/device/body_tracking.html)

PICO公式の`StartBodyTracking()`・`GetBodyTrackingData()`はUnity SDKのAPIであり、Webページから直接呼ぶAPIではありません。[PICO Unity Body Tracking](https://developer.picoxr.com/document/unity/body-tracking/)

WebXR Body Trackingは草案です。本実装はブラウザが実際に提供するデータを任意で使用し、未提供なら頭・手の取得を継続します。草案はARとVRを対象としますが、上記PICO構成のARモードを本アプリで検証した結果はありません。独自の`getBodyPose()`や未確認のネイティブ連携は使用しません。

## 生データ JSON

`format: 'vli.motion-capture'`、`version: 1`。メートル・右手系・Y上向きです。PICOでは原点は**収録室の待機中に最初に追跡できた頭部位置**、正面はその時の頭の水平方向です。グリップで合わせ直すと更新されます。録画開始時に原点を変更せず、ライブ表示と保存に同じ取得サンプルを使用します。時刻だけを録画開始後の最初の有効フレームで0にします。

- `referenceSpace`・`origin`: 使用した参照空間と校正変換。
- `fps`・`duration`: 保存頻度の上限（PICOは通常30Hz、カメラは15Hz）と最終フレーム時刻（最長180秒）。PICOのライブ表示はXR描画頻度で更新。
- `initialHeadHeight`: PICOではfloor空間で得た初期頭部高さ、それ以外は`null`。カメラでは頭と足首から推定できる場合のみ高さを保存。
- 任意の`accompaniment`: 内蔵曲との対応。`{ "track": "neon-door", "offset": 0 }`のように保存します。`offset`はモーション時刻0に対応する曲の位置（秒、0以上72未満）です。音源ファイルや外部URLは含みません。
- `frames`: 単調増加の`t`、`visibility`、`head`・`left`・`right`。追跡できないトラックは`null`。
- 各姿勢: `position: [x,y,z]`、`quaternion: [x,y,z,w]`、`emulatedPosition`。任意の`source`は`viewer`・`controller-grip`・`hand-wrist`・`camera-pose`。
- 任意の`body`: 草案の関節名から各姿勢へのマップ、または`null`。胴7関節、左右の肩・上腕・前腕・手首、左右の大腿・下腿・足首・足球の計23関節を対象とし、欠損は補わず、未知の関節名は取り込み時に除去。

従来の`source`・`body`・`accompaniment`のないJSONも読み込めます。未対応の曲、不正な開始位置、曲の残り時間を超えるモーションの参照は無視して無音で読み込み、外部URLを取り込みません。非表示・フォーカスを失ったフレームには姿勢を保存せず、長い空白や欠損をまたいで補間しません。取り込み上限は**32 MiB・180秒・最大60Hz**で、数値・時刻順・単位クォータニオン・バージョンなどを検証します。

カメラ収録は`referenceSpace: 'camera'`で区別します。腰中心に対する推定位置から初期の頭位置を引く座標系で、部屋に固定された参照空間ではありません。頭・手の`source`は`camera-pose`となり、身体を含む位置データの`emulatedPosition`は`true`として扱います。映像や元の画像データはJSONにも含めません。

## 診断と検証

「AR診断を保存」には収録の有効機能、頭・手の取得状態と入力元、身体APIの状態・関節件数・位置推定件数も保存します。座標・回転・関節そのものは含めません。詳細は[壁配置の診断](wall-placement.md#ar診断を保存する)を参照してください。

合成フィクスチャと自動テストは、校正・欠測・手首優先・身体データの検証・VRM 0/1の軸・補間・録画上限・モデルの姿勢適用を確認します。実機の精度確認とは別です。

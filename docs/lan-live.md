# インターネットなしで使うLANライブ

会場PC・Android・PICO・iPhoneを同じLANへ接続し、会場PCからアプリと姿勢データを配信します。**会場ではインターネット・公開DNS・GitHub Pages・CDN・STUN/TURNを使用しません。** Wi-FiルーターのWANを切断しても、端末とPCが通信できるWi-Fi/LANは維持します。端末のWi-Fi自体はオフにしません。

1ルームは出演者1人・合計16端末まで。出演者のカメラ推定またはHMDの動きを各端末のVRMへ反映します。観客はARで舞台と他の観客の簡易顔アバターを表示し、HMDは取得できた手も共有します。スマホ観客は端末位置を顔の目安に使い、手を共有しません。

**PICO 4 Ultra・Android・iPhone実機のオフラインLAN接続、CA証明書の信頼設定、AR動作、精度・遅延は未確認です。** 同梱物の確認やPC上のテストと、実機でのWAN切断試験は区別します。

## 事前にキットを作る

開発環境で依存パッケージを取得してから、会場用キットを生成します。この段階ではインターネットを使用できます。会場ではビルドやパッケージの取得を行いません。

```sh
npm ci
npm test
npm run offline:pack
```

出力は`artifacts/vli-bar-offline-<OS>-<CPU>/`です。今回の作成環境は**Mac / Apple Silicon（darwin-arm64）**。別のOS・CPU向けには、その環境に対応するNodeを含むキットを準備します。

キットにはビルド済みアプリ、Node実行環境、中継サーバー、WebSocket依存パッケージ、VRM・VRMA・音源、MediaPipeのJavaScript・WASM・身体推定モデル、ローカル説明ページ、印刷用マーカーと認識処理、ライセンスを含めます。ユーザーのVRM・収録・合言葉・秘密鍵はパッケージに含めません。**会場PCへのNode/npmの別インストールは不要**です。初回の証明書生成にOSのOpenSSLを使用します（Mac標準環境を想定）。

キット全体をUSB等で会場PCへコピーし、`dist/help/lan-offline.html`を開いておくと、サーバーの起動前でも操作手順を読めます。会場用ページは外部素材や外部リンク先の説明に依存しません。

端末側も事前準備が必要です。Chrome/PICO Browser/Safari・OSを利用可能な状態にし、AndroidのAR観客にはARCore対応端末とGoogle Play開発者サービス（AR）を用意します。インストールや初回ダウンロードが残らないよう、会場で使う端末ごとにカメラ・ARを一度起動して確認してください。iPhoneはSafariでカメラを使い、WebXRの代わりに印刷マーカーでAR表示します。キットの`dist/markers/index.html`を100%・実際のサイズで印刷し、黒い外枠を実測してください（既定15cm、白い余白を含む画像全体18.75cm）。黒い外枠の幅をアプリのマーカーサイズに設定します。これら端末側のソフトはWebアプリのキットには含みません。

## 会場で起動する

1. ルーターのWANを切断し、会場PC・Android・PICO・iPhoneを同じWi-Fi/LANへ接続します。「インターネットなし」と表示されても、そのWi-Fi接続を維持します。端末間通信を遮断するAP isolation / 端末分離は無効にします。
2. Macではキット内の`start.command`を実行します。ターミナルからは`./start.sh`も使用できます。内蔵Nodeで起動するため、`npm install`等は実行しません。
3. 私設IPv4の候補が1つなら自動選択し、複数ある場合は候補を表示します。実際に会場LANへ接続しているIPを指定して起動してください。

```sh
./runtime/node scripts/start-offline-lan.mjs --host 192.168.1.10
```

例のIPは会場PCの実際のIPへ置き換えます。ポートは既定で8443、変更する場合は`--port 8443`で指定します。PCのファイアウォールでは会場LANからそのポートへ接続できるようにします。起動したターミナルは終了まで開いておきます。

初回はキット内の`.lan-certs/`にローカル認証局と、そのIP用のサーバー証明書をオフライン生成します。認証局は以後も保持し、IPが変わった場合は同じ認証局でサーバー証明書を更新します。OSや端末の信頼設定は自動変更しません。認証局を削除・作り直すと、各端末でも再登録が必要になります。

## 各端末で証明書を信頼する

WebXRとカメラ取得には、安全なコンテキストとして認識されるHTTPSが必要です。ローカルネットワークでもこの条件は変わりません。証明書を生成することと、各ブラウザがその認証局を信頼することは別の設定です。

1. キット直下の`venue-ca.crt`を、USBや端末のファイル転送で各Android・PICO・iPhoneへ渡します。これは`.lan-certs/ca.crt`と同じ公開用証明書です。**配るのはこのCA証明書だけ**です。`ca.key`と`server.key`はPCに保持します。
2. Androidでは設定のセキュリティ／暗号化と認証情報にある証明書追加から、認証局（CA）証明書として登録します。メニュー名は機種・OSによって異なります。ブラウザにも信頼が反映されていることを確認します。
3. PICOも、端末・ブラウザが提供する証明書の信頼設定で登録します。**PICOで利用者のCAを信頼できる手順とWebXRへの反映は実機未確認**です。設定を利用できない場合、その端末をこのオフライン構成で使えるとは保証できません。会場へ持ち込む前に解決・確認してください。
4. iPhoneでは`venue-ca.crt`を端末へ渡して開き、設定から証明書のプロファイルをインストールします。続けて「設定」→「一般」→「情報」→「証明書信頼設定」で、その会場用CAの「ルート証明書を全面的に信頼する」を有効にします。インストールだけではHTTPS用の信頼は有効になりません。OSの画面名はバージョンによって異なります。信頼設定は利用者が手動で行い、アプリは自動変更しません。
5. 各端末で、起動時に表示された`https://192.168.1.10:8443/`を直接開きます。証明書エラーがなく、カメラ／ARの開始が可能なことを確認します。iPhoneではSafariで開き、カメラを許可してください。

PCだけに認証局を登録しても、スマホ・HMDは信頼しません。証明書警告を無視して続行する方法や、ブラウザの安全機能を無効にするフラグは使用しません。公開CA・公開DNSへの接続も、この会場手順には不要です。

## 配信・観覧する

1. 全端末で同じ`https://会場PCのIP:8443/`を開きます。会場サーバー自身がアプリ・素材・WSSの`/live`を提供します。「接続先（このページの会場PC）」は自動設定され、URL入力は不要です。
2. 「LAN ROOM」で同じルーム名・合言葉を入力します。ルーム名は英数字・`_`・`-`の1〜48文字、合言葉は12〜128文字。表示名と端末の種類も設定します。
3. 出演者は「出演者として配信」で参加し、「カメラを準備」または「HMDでモーションを収録」を開きます。**待機中から**有効な姿勢を配信します。必要なら同時に収録できます。
4. 観客は「観客として参加」。3D画面で受信を確認し、PICO・対応Androidは「ARでステージを開く」で配置します。iPhoneはマーカーARを開始してカメラを許可し、壁の印刷マーカーへ向けます。マーカーが見えている間だけ舞台を表示し、自分の端末位置を顔の目安として共有します。スマホの手は共有しません。
5. 「自分の姿勢をルームへ共有する」をオフにすると受信だけを続けます。終了時は「ルームから退出」。通信断後は参加ボタンで入り直します。

最初の参加でルームと合言葉が決まり、最後の退出またはサーバー終了で消えます。アカウント認証・出演者専用の管理権限はなく、同じ合言葉を持つ人は空いている出演枠を使用できます。

## 全員で舞台の位置を合わせる

各端末のAR原点は異なります。全員が**同じ壁の同じ舞台中心・幅・向き**に舞台を置いてください。iPhone用のARUCO_MIP_36h12・ID 0マーカーは、矢印を上にして舞台の開口部の中心へ貼ります。iPhone同士は同じマーカー・実測サイズを使い、舞台幅も全員で合わせます。印刷マーカーと認識処理はキット内にあり、外部サービスへ接続しません。

WebXRの配置原点は舞台の下端中心です。マーカー中心から**舞台幅 × 2.5 ÷ 2.4 ÷ 2**だけ下がった点を下端中心にしてください（幅2.4mなら1.25m下）。HMDの3点指定では同じ左下・右下・左上を指定します。自動候補・Androidのタップ配置でも下辺を目で合わせ、ずれたら再配置します。[壁への配置手順](wall-placement.md)

iPhoneのマーカーARは、カメラにマーカー全体と白い余白が見えている間の位置推定です。壁の自動検出・部屋のSLAM・永続アンカーではありません。カメラ画角は近似値を使うため、距離・大きさ・観客位置に誤差があります。印刷精度、照明、傾きでも追跡が揺れます。マーカーを見失うと舞台と位置共有を止め、再検出すると戻ります。ARと身体モーション収録はカメラを共有できないため、終了してから切り替えます。WebXRとマーカーARの間で自動の共有空間合わせ・端末間測量は行わないので、混在時は目視で位置を揃えてください。

## 通信と保存の範囲

- カメラ画像・マイク音声・VRMファイルを出演者端末から他の参加者へ送りません。カメラ処理は端末内で行い、推定された頭・手・身体関節だけを中継します。カメラの絶対移動や顔表情は計測しません。
- スマホ観客はAR端末位置の簡易顔アバターのみ。HMD観客は頭と取得できた手を表示します。実写の顔・表情・口の動きは配信しません。
- 音声配信と端末間の曲同期は未実装です。同梱曲を会場PCとスピーカー等で再生できます。
- 通信は標準WebSocket上の一時的な姿勢メッセージです。外部中継・STUN/TURNは不要です。約20Hzを上限に送り、遅い推論では同じ姿勢が続く場合があります。取得停止・古い姿勢は隠します。
- サーバーは映像・モーション履歴を保存しません。手動で収録したデータは端末内に保存し、交換には標準VRM Animation 1.0（.vrma）を使います。計測JSONは元データ保存用です。[モーション形式](motion-formats.md)

## 検証と開発用テスト

2026-10-04のPC実ブラウザ検証では、同梱Node・中継サーバーと外部originを禁止するCSPの下で、9項目すべてが通過しました。同梱VRM（592,456 bytes）、標準VRMA（72秒）、音源（72秒・2ch・デコード後48kHz）を実読み込みし、ローカル画像の合成映像を実MediaPipe WASMで推論して5フレーム・身体23関節を取得しました。3つの実WebSocket接続で姿勢を中継し、スマホ観客の頭のみ／HMD観客の両手を確認。読み込んだ14資源は外部origin 0、CSP違反0でした。

自動テストは178件すべて通過。同梱ランチャーも`PATH=/usr/bin:/bin`で、追加のNode/npmを使わず8790番ポートへ起動できました。**実カメラ、Android・PICO・iPhone実機、物理的にWANを切断した会場LANでは未確認**です。今回の資源・通信検証だけで、それらの動作を保証するものではありません。

会場前にWANを切ったLANで新しくページを開き、素材表示、曲、カメラ推定、出演者と複数観客の接続、手動位置合わせ、退室を順に確認します。外部通信を使わないアプリ構成であっても、未準備のOS・ブラウザ・ARサービスのダウンロードまでは代替できません。

キットのファイル整合性は次のコマンドで確認できます。

```sh
./runtime/node scripts/build-offline-kit.mjs --verify .
```

待ち受けを始めずに配布ファイルと証明書の準備を確認する場合は、`./runtime/node scripts/start-offline-lan.mjs --host 会場PCのIP --check`を使用します。

開発環境のPC内だけで通信を確認する場合は`npm run build`後、`npm run lan:localhost -- --port 8080`と`npm run dev`を起動し、`http://localhost:5173/tests/browser/live-smoke.html`を開きます。Connect → Run → Leaveで3クライアント・8項目を検証します。連続合成姿勢モードでは、**実アプリは`http://localhost:8080/`で開き**、表示されたルーム名・合言葉を入力して4台目の観客にします。Viteの5173番や公開Pagesでは会場サーバーの設定が得られないため、アプリのLAN参加は有効になりません。入力は合成データで、実機追跡のテストではありません。localhost HTTP起動はループバック専用で、会場LAN実機用ではありません。
